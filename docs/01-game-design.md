# 产品与游戏设计

> 本文描述目标产品。仓库已经实现逐日开放模拟的首个可玩 MVP；完整职业生涯和更深的制度模拟仍属于后续范围。

## 1. 产品愿景

玩家扮演一名虚构的中国地方领导干部，在组织体系、行政体系和地方社会之间工作。游戏按自然日持续推进，不以预先写好的六回合或十二周脚本规定玩家必须在何时遇到什么。

玩家每天面对不断变化的晨报、文件、人物、会议和日程，在有限时间内决定：

- 今天亲自关注什么，什么交给别人；
- 听谁汇报、相信谁、还要核实什么；
- 用会谈、调研、会议、批示还是向上报告处理问题；
- 哪些事项可以授权，哪些必须进入正式程序；
- 对谁作出什么承诺，以及准备承担何种责任；
- 何时结束一天，让下属和外部世界继续行动。

游戏最终可以从一次地方任职延伸到调任、晋升、处分与退休。但在逐日模拟被验证前，不扩展完整仕途系统。

## 2. 体验目标

一局成功的游戏应当让玩家持续感到：

1. 我拥有重要权力，但一天只能亲自处理少数事情。
2. 我看到的是经过别人筛选、解释和延迟的信息。
3. 人不是事件选项的装饰；他们会说话、沉默、起草文件、互相通气、拖延或自行行动。
4. 会议不是一个“通过方案”按钮，而是信息、立场、程序和责任共同形成的过程。
5. 文件不是背景文本；它可以被起草、修改、退回、转交、签发和追责。
6. 日程安排本身就是政治选择，今天答应下周调研，会挤占下周真正发生危机时的时间。
7. 重大后果不必立刻显现，也可能因条件始终不满足而不再出现。
8. 我决定方向、红线、授权和重大分歧，而不是亲自填写全部预算与执行清单。

游戏不追求让玩家背诵制度名词。制度通过谁能决定、需要何种会议、要等多久、留下什么记录以及谁承担后果，变成可感知的玩法。

## 3. 玩家职责边界

### 3.1 玩家应当决定

- 当前工作的目标、优先级与不可突破的红线；
- 哪些问题进入议程，何时讨论，邀请谁参加；
- 是否先调研、核查、个别酝酿或向上请示；
- 把起草、协调和执行交给谁；
- 如何处理跨部门分歧、重大风险和责任分配；
- 是否形成公开承诺、会议决定或书面报告；
- 对执行不力者督促、保护、调整分工或启动相应程序。

### 3.2 玩家通常不直接决定

- 具体工程和技术路线；
- 逐项预算、采购、融资和部门内部人员安排；
- 常规行政文书、宣传稿、项目排期和工作清单；
- 属于市长、分管领导、部门或区县权限内的日常事项。

玩家可以越级介入，但会增加时间消耗、责任暴露和组织依赖，也可能削弱原有责任链。

### 3.3 指令与执行的层次

玩家原话不会直接改写世界。它可能依次形成：

```text
谈话或批示
  ↓
目标、红线、授权或核查任务
  ↓
下属起草方案或文件
  ↓
必要的协调、审查与正式会议
  ↓
取得效力的决定或正式文件
  ↓
具体人物和机构执行
  ↓
执行反馈、偏差与责任痕迹
```

不是每句话都必须走完整链条。查询事实、要求起草等准备性事项可以直接成为任务；重大资金、政策、人事和跨部门决定则必须经过有权限的程序。

## 4. 时间模型与每日循环

### 4.1 时间单位

游戏基本时间单位为一个自然日。日期连续推进，工作日、周末、节假日、天气、出差和重大活动可以改变可用日程，但不改变“一天一结算”的基本单位。

剧情不再按“第一回合收材料、第四回合开常委会、第六回合复核”推进。问题拥有自己的期限、条件和演化速度；玩家可以提前处理、长期搁置、改变路径，或让它与其他问题相互挤压。

### 4.2 每日状态机

```text
生成晨报
  ↓
玩家阅读来文、查看日程、处理无需行动点的批示
  ↓
执行当日已预定或临时加入的行动
  ↓
会议 / 面谈 / 调研 / 向上面谈可分别触发场景结算
  ↓
玩家继续使用剩余行动点，或主动结束一天
  ↓
日终世界结算
  ↓
下属行动、文件起草、外部反应、新闻与延迟触发器推进
  ↓
日期前进，形成次日晨报
```

玩家不需要把当天行动点全部用完。未使用的行动点不结转；提前结束一天意味着把时间留给既有组织链条运行，也意味着放弃亲自介入当天的新机会。

### 4.3 一天结束的条件

以下情况允许结束一天：

- 没有正在进行的互动场景；
- 当日强制日程已经完成、被正式取消或明确拒绝；
- 所有已打开但尚未提交的玩家决定均已保存为草稿或放弃；
- 玩家确认让剩余事项进入次日或后台处理。

紧急事件可以在玩家结束日之前插入；一旦进入日终结算，本日不能再补做行动。

## 5. 晨报

每天开始生成一份带来源的晨报，而不是抽象的“事件卡”。晨报至少包括：

1. **昨日与夜间要闻**：媒体报道、公开通报、舆情变化和外部事件；
2. **内部报告**：部门、区县、专班和秘书系统提交的进度、风险和数据；
3. **请示事项**：需要玩家批示、退回、转办或决定是否上会的文件；
4. **上级信息**：通知、指示、询问、报送期限和临时召见；
5. **今日日程**：已预约会议、调研、面谈、固定活动和冲突；
6. **到期提醒**：承诺、任务、报告、会议准备和程序期限；
7. **未核实信息**：传闻、私下提醒和相互矛盾的口径，明确标记来源性质。

晨报只展示玩家渠道能够获得的信息。昨夜发生的世界事实如果没有进入媒体、报告或人物渠道，不会自动出现在晨报中。

为避免无限信息淹没玩家，秘书系统会按紧急性、职责相关性和玩家既往偏好排序，但玩家可以打开完整收件箱和历史档案。排序可能有偏见或遗漏，因此“秘书把什么放到最上面”本身也是可观察的组织行为。

## 6. 行动点与行动

### 6.1 默认预算

基础规则暂定每天 **4 个行动点**，由场景配置调整。行动点代表领导者可支配的完整注意力和时间块，不等于现实中的精确小时。

| 行动 | 默认消耗 | 说明 |
|---|---:|---|
| 找一人面谈 | 1 | 包括一段连续会话和该场景的结算 |
| 召开或参加一般会议 | 2 | 参会者越多不会额外扣点，但准备与可用性受规则约束 |
| 市委全会等大型正式会议 | 3 | 需要预先准备、通知和达到相应条件 |
| 现场调研 | 2 | 通知调研与“四不两直”消耗相同，信息结构和风险不同 |
| 与上级面谈 | 2 | 还受上级日程、出行和召见条件影响 |
| 审阅、批示、退回、转交文件 | 0 | 只处理已经到达玩家收件箱的有限文件 |
| 提交一份已经就绪的书面报告 | 0 | 起草和修改需要现实中的后台时间，但不额外占玩家行动点 |
| 安排未来日程 | 0 | 在执行日而非预约日扣除行动点 |

这些数值是首轮试玩参数，不是永远不变的设定。行动开始后才扣点；同日临时取消可能消耗部分点数并产生关系或准备成本。

### 6.2 不消耗行动点不等于没有约束

批阅文件不消耗行动点，是为了让玩家保持领导者的工作节奏，而不是制造无限操作漏洞：

- 玩家只能处理真实到达的有限来文，不能凭空反复刷新材料；
- 一份批示只能产生其权限允许的效果；
- 复杂批示可能被解析成起草、核查或上会任务，仍需等待后台完成；
- 大量越级批示会造成责任混乱、下级依赖和秘书系统负担；
- 已签发或已提交文件不能无痕改写，只能形成新版本、补充文件或撤回记录。

### 6.3 自由度来自组合，而不是无限按钮

玩家可以用自由文本表达讲话、问题、批示、议程和报告意见。系统把自由文本解析为有限的领域意图，并显示关键理解。缺少执行细节时交给被授权 NPC；只有会改变政治方向、权限或责任的歧义才追问玩家。

## 7. 日程管理

### 7.1 日程条目

每项日程保存：

- 日期和大致时段；
- 行动类型、地点、参与者和发起人；
- 预计行动点；
- 是否强制、可否改期、取消期限和优先级；
- 需要提前完成的材料、安保、通知或程序；
- 关联议题、保密范围和预期产物；
- 接受、暂定、冲突、执行、取消、缺席或完成状态。

### 7.2 预约与执行

玩家今天可以预约未来某日调研、会议或面谈。预约时预留未来行动点，执行日自动进入当日日程并在开始时扣点。玩家不必再次选择“是否执行”，但仍实际参与该互动。

参加人不保证随叫随到。秘书系统会根据其日程、职务和关系返回接受、建议改期、派代表或拒绝。紧急召集可以提高到场优先级，也会增加准备不足和日程冲突成本。

### 7.3 冲突与强制事件

- 玩家不能主动预约超过当日预算的确定日程；可以建立“暂定”条目等待冲突解决。
- 上级临时召见、突发事件和法定固定活动可以挤入已满日程。
- 出现冲突时，玩家需要改期、取消、委托他人或拒绝其中一项；不能让两个互斥场景同时发生。
- 取消已经投入大量准备的会议或调研会影响参与者、信息时效和组织信用。
- 强制日程不是“系统替玩家玩完”：它会在对应时段自动开启，玩家仍要发言、提问或作出回应。

## 8. 会议系统

### 8.1 两个独立维度

会议必须区分：

1. **制度类型**：市委全会、常委会、书记专题会、议事协调会、工作会、座谈会、政府常务会等；它决定成员、权限、程序、是否能够表决和正式效力。
2. **讨论方式**：无主持自由磋商或由玩家主持点名；它决定发言如何产生，但不会自动改变会议权限。

例如，座谈会即使由玩家主持也不能替代常委会作出重大决定；常委会即使采用较自由的发言方式，仍需满足法定人数、讨论、表决和记录要求。

### 8.2 会前准备

玩家或秘书系统需要确定：

- 会议类型、议题和目标；
- 出席成员、列席人员、汇报人和是否回避；
- 采用自由磋商还是玩家主持；
- 材料是否就绪，是否允许临时材料；
- 会议可以形成讨论意见、准备任务还是正式决定；
- 预计时长和行动点。

准备不足不一定禁止开会，但可能使会议只能听取情况、退回补充或形成临时任务，无法合法有效地作出某些决定。

### 8.3 无主持自由磋商

每一轮按以下顺序运行：

1. 系统冻结当前会议记录版本；
2. 所有尚在场的 NPC Agent 基于自己的认知和记忆，并行判断是否想发言；
3. 若无人愿意发言，界面显示沉默，玩家可以发言、点名、改变问题或结束会议；
4. 若恰有一人愿意发言，由该 Agent 生成发言；
5. 若多人愿意发言，使用带种子的随机数在候选人中选出下一位，并记录抽样结果；
6. 发言进入全体在场者的可听记录，然后开始下一轮。

Agent 的“想发言”输出只包含是否发言、想回应的对象和意图摘要，不提前生成完整发言。这样可以并行判断而不浪费大量被丢弃的文本。

### 8.4 玩家打断

玩家在任何 NPC 发言生成期间选择说话时：

- 当前生成任务收到取消信号；
- 已经显示但尚未确认的流式文本从正式记录中移除；
- 即使供应商稍后返回完整结果，也因生成令牌失效而被丢弃；
- 被取消内容不进入任何人物记忆、不形成承诺，也不改变状态；
- 玩家发言优先写入会议记录，所有在场人物据此更新后续判断。

技术上无法保证模型供应商停止计费，但可以保证取消输出没有游戏效力。

### 8.5 玩家主持点名

由玩家掌握发言顺序：

- 点名某人汇报、回应或表态；
- 允许列席者说明事实；
- 自己发言、追问、归纳分歧；
- 暂停议题、退回补充或转入表决；
- 看见他人“请求发言”，但是否点名仍由玩家决定。

正式会议可以配置主持人的发言顺序约束，例如岚州市可采用书记末位表态作为本地规则。

### 8.6 表决与正式效力

Agent 负责表达立场和理由，规则内核负责：

- 参会资格和法定人数；
- 谁有表决权、谁仅列席；
- 表决方式和通过门槛；
- 决定是否超越会议权限；
- 是否仍需政府、部门或其他法定程序；
- 纪要、签发和责任记录。

“公开行动都必须开常委会”过于宽泛。部门权限内的常规公开行动可以依法执行；涉及重大政策、大额资金、人事、跨部门责任或场景规则要求集体研究的事项，才必须进入相应正式会议。系统应说明缺少的是哪一层权限或程序。

### 8.7 会后结算

会议结束后先冻结逐字记录，再进入一个有界的会后结算轮：

1. 每名参会 Agent 独立提取自己听到的事实、承诺、任务和他人立场；
2. Agent 可以提出至多若干项后续意图：与人通气、请求信息、起草文件、提交报告或准备行动；
3. Agent 之间的私下交流按渠道和知情范围生成新的会谈记录；
4. 文件意图变成有作者、期限和收件人的后台起草任务；
5. 行动意图交给规则内核检查权限、资源、已有决定和所需程序；
6. 允许立即开始的准备或权限内行动进入执行队列；需要玩家或会议批准的行动转为请示、议题建议或草案；
7. 会后记忆写入各自私有记忆，不把全体人物的理解强行统一。

为防止 Agent 无限互聊，会后每人有意图上限，交流只展开一跳；新的回复和连锁行动进入日终或未来日期。

## 9. 个别面谈

面谈是玩家与一名角色的连续会话，默认消耗 1 个行动点。创建时需明确：

- 对象、地点和渠道；
- 是否有秘书或其他人在场；
- 是否形成正式谈话记录；
- 当前议题与玩家希望了解、试探或交办的内容；
- 保密预期，而非不可能兑现的“绝对保密”。

NPC 只使用自己的身份、局部认知、亲历记忆和可读文件作答。玩家可以询问、试探、说服、批评、非正式交办或提出条件。重大决定不会因为对方口头同意而立即生效。

面谈结束后也运行会后结算：对方可以联系别人、起草材料、执行权限内的准备行动、隐瞒部分内容或改变下一步计划。玩家无法直接看到这些隐藏行为，除非它们通过文件、传闻、执行或其他渠道暴露。

## 10. 现场调研

### 10.1 两种方式

- **有通知调研**：更容易获得完整接待、正式材料和关键人员，但现场可能被提前布置，问题可能被筛选。
- **“四不两直”式调研**：减少提前准备和层层陪同，更可能看到日常状态；同时可能遇到进不去、负责人不在、材料拿不到、样本偶然或安全保障不足。

两者默认均消耗 2 个行动点。“不打招呼”不是购买真相的技能，观察结果仍取决于地点、时段、在场人员、玩家专业判断和可复现随机条件。

### 10.2 调研生成

规则内核先确定玩家能够观察到的结构化事实：

- 实际到达地点和可访问区域；
- 当时存在的人员、设备和活动；
- 被提前布置或临时隐藏的内容；
- 可见异常、文件和口头说法；
- 观察局限、样本偏差和后续可核查线索。

LLM 只把这些已确定内容叙述成现场，不得凭气氛创造新的重大世界事实。调研过程中可以进行有限的现场提问，它属于同一次行动，不额外扣点。

调研结束后，陪同人员、属地和被调研单位都会形成自己的认知与反应，并进入场景结算。

## 11. 向上汇报

### 11.1 书面报告

书面报告必须提交一个游戏内文件。玩家可以：

- 让秘书或责任部门起草；
- 退回修改并附批示；
- 在下级报告上增加呈报说明；
- 原样转呈下级文件；
- 选择附件、签发范围和报送对象。

原样转呈不会抹掉文件来源、版本和缺失信息。上级 Agent 能够看到这是玩家亲自形成的报告、秘书代拟后签发的版本，还是未经改写的下级材料。

报告就绪后的阅读、签发和提交不消耗行动点；起草、核查和修改需要 Agent 工作量与游戏时间。逾期、仓促签发和绕过核查都会留下后果。

### 11.2 与上级面谈

面谈逻辑与玩家和下级的会谈相似，但玩家不掌握上级日程，也不能强制对方接受。场景中上级同样只有其渠道掌握的信息、既往评价、当前任务和对玩家的记忆。

上级可以当场追问、口头指示、表示保留、要求补报，或不作明确表态。口头意见的正式效力与书面指示、会议决定不同。

### 11.3 延迟反应

上级在收到报告或结束面谈后提出结构化反应意图，例如：

- 立即回复或要求补充；
- 在某个日期窗口调研、约谈或检查；
- 在某些条件满足后调整资源、评价或监督强度；
- 暂不采取行动；
- 让事项进入休眠，不保证以后一定触发。

Agent 决定的是政治意图和关注方向；模拟内核验证权限、条件和时间，并决定是否建立延迟触发器。已经失效的关注应关闭或设置过期条件，不能保留一个每天无期限扫描的幽灵事件。

## 12. 游戏内文件系统

文件是具有权限和生命周期的领域对象，而不是一段随意覆盖的文本。

### 12.1 常见文件

- 晨报、要情、调查材料和情况说明；
- 请示、报告、批示、通知和函件；
- 会议议程、汇报稿、记录、纪要和决定；
- 方案、风险评估、合法合规意见和数据附件；
- 上级来文、下级报文、群众来信和公开稿件；
- Agent 的工作草稿、内部便笺和个人笔记。

### 12.2 文件元数据

每个文件版本至少保存：

- 文件 ID、版本、标题、类型和密级/知情范围；
- 作者、起草单位、形成时间和关联议题；
- 收件人、抄送人、当前保管范围；
- 草稿、送审、已提交、退回、批准、签发、公开或归档状态；
- 引用材料、附件、前后版本和修改来源；
- 是否具有正式效力、由谁签发、依据何项决定；
- 预计完成、实际提交和阅读时间。

提交后的版本不可静默改写。修改必须生成新版本，并保留差异与沿革。

### 12.3 Agent 的文件权限

Agent 获得的是游戏内虚拟文件能力：

- 搜索自己有权访问的文件；
- 读取被授权版本；
- 创建和修改自己的草稿；
- 基于现有文件派生新版本；
- 提交给有权接收的人或机构；
- 附加说明、请求会签或退回修改。

Agent 不获得主机文件系统、Shell、任意网络或数据库写权限。正式文件的效力由权限、签发与程序决定，不能由 Agent 调用“写文件”工具直接创造。

## 13. 日终结算与动态世界

每天结束后按固定顺序结算：

1. 冻结本日玩家动作、会议记录、谈话和文件版本；
2. 完成本日到期的后台任务与文件起草；
3. 激活与任务、责任、事件或近期互动有关的 NPC，而不是让全城所有人常驻运行；
4. NPC 提出沟通、文件、调查、执行、拖延、上报等结构化意图；
5. 规则内核检查权限、资源、程序、冲突和优先级；
6. 使用带种子的随机流结算外部冲击、执行偏差和信息传播；
7. 更新世界事实、人物认知、任务、承诺、证据和关系；
8. 建立、满足、延期、取消或关闭未来触发器；
9. 从已结算事实生成公开新闻、内部报告、请示和次日来文；
10. 压缩人物情节记忆，但不删除正式记录；
11. 生成次日晨报并推进日期。

LLM 不决定指标增减或某项行动是否“成功”。它表达人物意图、起草文本和叙述已结算结果；规则内核决定有效性和状态变化。

## 14. 事件与变化度

事件不再是固定日期剧本，而来自四个来源：

- **既定义务**：上级期限、会议周期、合同、预算、天气季节和法定程序；
- **内生后果**：玩家决定、承诺、执行偏差、财政与社会状态的继续演化；
- **人物主动行为**：NPC 的上报、游说、拖延、核查、文件和权限内行动；
- **条件化外部冲击**：由场景规则提供候选类型、触发条件和强度范围，再由带种子随机源抽样。

LLM 可以为已经合法生成的事件填充合乎上下文的表达和非关键细节，但不能凭空创造一笔巨额资金、一项上级批准、一次事故结论或一项正式决定。

同一开局应因玩家日程、信息渠道、人物互动、文件流转和随机种子产生不同进程，而不是把同一六段故事换一种措辞。

## 15. 权力、关系与利益交换

正式权力包括议程、召集、授权、监督、公开承诺、向上沟通和人事影响。非正式政治资本包括按议题区分的信任、依赖、声望、信息渠道、人情债和责任共同体。

交换可以围绕政策空间、资源顺序、风险保护、及时报告、承担任务和公开支持展开。每项承诺结构化保存承诺人、受益人、内容、条件、期限、知情范围、履约状态和违反后的反应。

私下谈话适合改变信息、立场、关系、准备任务和条件承诺，不能绕开必须集体讨论或依法履行的程序。违法违规选择会形成审计、举报、纪律和长期责任风险；游戏不提供现实规避监督的操作指南。

## 16. 信息、认知与人物

每项重要信息区分：

1. **世界事实**：模拟内核保存的实际状态；
2. **人物认知**：某个角色知道、相信、误判或怀疑的内容；
3. **材料版本**：以具体文件或口头渠道呈现给某些人的说法；
4. **公开叙事**：新闻、通报和社会传播中的版本。

重要 NPC 具有稳定履历、正式权限、能力、风险偏好、程序意识、沟通风格和长期目标，也具有会随时间变化的任务、压力、关系、立场、记忆、文件和行动计划。

人物不能被压缩为“忠诚、贪婪、清廉、派系”等单一数值。同一人可以同时维护公共利益、部门利益、个人前途和程序责任。

## 17. 指标与长期结局

城市状态至少覆盖财政、产业就业、民生、生态、社会矛盾、安全、行政执行能力和历史负担。玩家职业状态包括上级评价、班子信任、重大工作、责任暴露、可用干部、信息渠道、年龄与履历。

多数软状态只以趋势、来源判断和事件证据呈现，不显示精确好感度和成功率。

完整产品可以一直推进到调任或退休。退休结算展示任期公共结果、留给继任者的负担、干部后续发展、承诺履约、离任后审计与不同群体的评价。当前阶段只设计这些接口，不实现完整仕途。

## 18. 内容基调与制度边界

- 城市、人物、企业、数字和具体事件均为虚构；
- 不使用真实在任官员作为 NPC，不影射未公开个人信息；
- 不把人际关系写成解释一切的万能变量；
- 所有重大事件至少有两个合理但有代价的方向；
- 认真调研、诚实报告、合法补偿和建设行政能力具有长期游戏价值；
- 不保证善意必胜，也不把犬儒与腐败写成唯一聪明策略；
- 会议权限、程序与党政衔接以 [地方党委组织与议事决策程序研究](04-local-party-committee-organization-and-procedure.md) 为制度骨架。

## 19. 当前关键设计决策

已经确定：

- 取消固定十二周六回合产品结构，改为逐日开放模拟；
- 每日晨报、有限行动点、零行动点文件批阅和日终结算构成基础循环；
- 会议的制度类型与主持方式分开建模；
- 自由磋商采用并行发言意愿判断和带种子随机选人；
- 玩家发言拥有中断优先权，被取消生成不进入状态或记忆；
- 会议和面谈结束后都有有界的 Agent 后续行动轮；
- 玩家可以预定未来日程，执行日扣除行动点；
- 文件是有版本、权限、来源和正式效力的领域对象；
- 上级可以即时、延迟、条件化或不作进一步反应；
- Agent 能操作游戏内文件与提议行动，但不能直接改写世界。

仍需试玩校准：

- 每天 4 点以及各类行动成本是否合适；
- 一次会议适合多少轮发言、何时提示收束；
- 会后每名 Agent 可提出多少项后续意图；
- 日终激活多少 NPC 才能兼顾变化度、成本和可理解性；
- 晨报默认展示多少条目、秘书排序偏差应有多强；
- 玩家是否需要可选的“快速推进数日”功能。

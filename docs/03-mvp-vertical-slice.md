# 最小可玩纵向切片：岚州市开放日程模拟

> 本文中的地区、人物、企业、数字和事件均为虚构，仅用于游戏原型设计。

> 本文取代原来的“十二周六回合产业整改”方案，并作为当前逐日 MVP 的验收基线。

## 1. 验证目标

新的最小可玩版本不是一条按周解锁的故事，而是一个可以连续推进日期的地方治理沙盒。它要验证：

1. 玩家每天能从晨报、日程和文件中自行决定关注顺序；
2. 会议、面谈、调研、批示和向上汇报是可组合的行动，而不是剧情节点；
3. 每名 NPC 在会议与会谈中只使用自己的认知和记忆；
4. NPC 会在场景结束和日终主动通气、起草文件或提出行动；
5. 文件从草稿到提交、签发和执行有可追溯流程；
6. 预定日程、强制召见和突发事件会争夺未来行动点；
7. 同一初始局面可以产生不同日期、不同顺序和不同结果；
8. 任何后果都能追溯到规则、人物、文件、资源、程序或带种子随机事件，而不是 LLM 随意裁定。
9. 角色能够在发言前按权限查阅完整文件和亲历记录，并在结算时结构化保存认知、记忆、待办和承诺。

MVP 可以设置“连续游玩 7—14 个游戏日”的试玩评估窗口，但不能在第 7 天或第 14 天强制结局。玩家只要愿意就可以继续推进。

## 2. 玩家身份

- 玩家 43 岁；
- 新任中部虚构地级市“岚州市”市委书记，到任三周；
- 此前有省级部门与另一地级市工作经历；
- 对政策熟悉，但本地信息渠道和班子关系尚未建立；
- 前任已经调离，留下若干模糊纪要、未完成事项和口头承诺。

开局可输入姓名并选择一项履历侧重，例如产业、县域、政法或综合部门经验。履历只改变部分初始认知、人物预期和调研判断，不提供全知视角。

## 3. 城市与持续问题

岚州市位于虚构的澄江省中西部，国土面积约一万二千六百四十平方公里，常住人口约三百七十八万。低山丘陵与河谷平坝相间，南川河穿过中心城区；多年降水约六成五集中在五月至九月。二〇二五年地区生产总值约二千一百四十八亿元，以能源化工、装备制造、农产品加工和商贸物流为主，一般公共预算收入约一百五十六亿元、支出约四百二十七亿元。

全市辖六个县级行政区，以下是玩家和所有 Agent 开局即可查阅的公开基线：

| 县区 | 常住人口 | 地区生产总值 | 主要特征 |
|---|---:|---:|---|
| 南川区 | 约 76 万 | 约 502 亿元 | 市级机关驻地，商贸服务、装备制造、老城排涝 |
| 临江区 | 约 62 万 | 约 486 亿元 | 老工业城区、港站物流、城市更新与土壤治理 |
| 北山县 | 约 71 万 | 约 423 亿元 | 焦化及上下游集中，县域财政和就业依赖度高 |
| 东宁市 | 约 66 万 | 约 368 亿元 | 县级市，平原农业、食品加工和轻型装备 |
| 青源县 | 约 55 万 | 约 215 亿元 | 西部山区、水源涵养、生态农业和文旅 |
| 和州县 | 约 48 万 | 约 154 亿元 | 农业、劳务输出和基本公共服务权重较高 |

公开资料还包括人口就业、教育医疗、交通能源和防灾基础。它们提供共同背景，不包含内部排查、企业经营秘密和当天动态。

MVP 同时运行三个问题，不让一个产业事件独占全部游戏。

### 3.1 北山产业整改

- 北山县焦化产业贡献重要税收与就业；
- 省级部门要求在近期提交一份可核验的阶段整改方案；
- 县、企业、工信与生态环境部门对就业、资产和整改进度的口径不一致；
- 该问题没有固定“第几天银行停贷”或“第几天复核”的剧本，后续取决于报告、融资、企业行动、上级安排和随机条件。

### 3.2 市级财政与项目排序

- 财政空间偏紧，多个部门希望把本领域项目列为优先；
- 市政府正在准备滚动支出安排；
- 玩家对产业整改作出的资源承诺会挤压其他议题；
- 资金问题通常需要市政府和有关部门程序，不能由市委书记一句话直接生成预算。

### 3.3 汛期准备

- 岚州即将进入多雨时段；
- 两处县区上报的水利风险等级不同；
- 是否提前调研、要求复查或接受现有报告，会影响以后出现极端天气时的准备状态；
- 天气候选由场景和随机种子驱动，不保证每局都发生灾情。

三个问题有不同速度：产业与上级期限较紧，财政持续积累，汛期风险可能长期没有显性后果。玩家无法每天同时亲自关注所有问题。

## 5. MVP 角色

### 5.1 市级班子与秘书系统

**周立衡，市长**

- 主持市政府工作，掌握财政与行政执行链；
- 支持整改，但反对无资金来源的政治表态；
- 知道一家主要企业可能出现流动性问题；
- 希望新书记尊重政府职责，而不是越级指挥部门。

**唐敏，市委秘书长**

- 负责议程协调、材料流转、日程与督查联络；
- 能帮助玩家安排会议、调研和文件起草；
- 怀疑县里就业口径偏低，但没有确证；
- 会根据玩家长期偏好调整晨报排序。

**罗志诚，常务副市长**

- 分管发展改革、财政、国资等工作；
- 希望推动市属国企参与产业整合；
- 方案能力强，也在寻找个人可见成绩；
- 其融资设想可能形成政府责任风险。

**邵文远，分管工业副市长**

- 熟悉产业与企业；
- 强调维持生产和就业，倾向争取更多时间；
- 担心过去两年的延期判断受到追责；
- 与企业接触多，知道一些未写入正式材料的承诺。

**贺兰，市纪委书记、市监委主任**

- 关注程序、数据、资金责任和不同意见记录；
- 不反对承担改革风险，但反对虚假数据和口头兜底；
- 已收到一封尚未核实的县企关系反映。

## 6. 第一天晨报种子

第一天只定义初始输入，不定义以后必须发生的顺序。

### 6.1 昨日新闻

- 《岚州日报》报道北山县召开产业转型推进会，未提具体停产范围；
- 本地网络出现一段焦化园区夜间排放视频，拍摄时间和地点尚未核实；
- 气象部门发布未来十天降水趋势提示，不构成确定灾情。

### 6.2 内部报告与请示

1. 生态环境局提交《北山焦化阶段整改情况报告》，建议尽快明确第一批核验对象；
2. 北山县提交《关于支持重点产业稳岗的请示》，就业数字低于工信部门估计；
3. 市财政局提交财政承受能力提示，要求任何新增支持先说明资金来源；
4. 水利局提交汛前排查汇总，两个县区附件口径不一致；
5. 省委办公厅通知：五个游戏日内报送一份北山整改简要情况，是否安排面谈另行通知。

### 6.3 初始日程

- 今日没有强制会议；
- 三日后有一次例行常委会暂定时段，议题尚未最终确定；
- 玩家可以把北山事项列入议程，也可以认为材料不成熟而暂不上会；
- 未来日期没有预写的产业事件，只保留上级报送期限和正常制度日程。

## 7. 每日可用操作

每天默认 4 个行动点。

### 7.1 消耗行动点

- 与一名角色面谈：1 点；
- 召开或参加一般会议：2 点；
- 现场调研：2 点；
- 与上级面谈：2 点；
- 大型正式会议：3 点。

### 7.2 不消耗行动点

- 阅读已经收到的文件；
- 批示、退回、转交和归档；
- 提交已经就绪的上级报告；
- 查看人物公开档案和自己的历史记录；
- 安排未来日程。

### 7.3 可预定的行动

玩家可以安排未来某日：

- 去北山焦化园区通知调研或“四不两直”调研；
- 召开座谈会、书记专题会、协调会或符合条件的常委会；
- 约谈某名角色；
- 向上级申请面谈；
- 要求秘书和部门在会前准备特定材料。

预定活动在执行日自动开启并扣点。参与者可能建议改期或派代表，上级也可能临时改变玩家日程。

## 8. 最小会议体验

MVP 至少支持四种会议制度类型：

| 类型 | 主要用途 | 正式效力 |
|---|---|---|
| 座谈会 | 听取企业、群众、专家或部门意见 | 不直接形成重大决定 |
| 书记专题会 | 酝酿方案、协调分歧、决定继续准备什么 | 不能替代常委会 |
| 工作协调会 | 推动已有任务、协调权限内执行问题 | 不得越权作出新重大决定 |
| 市委常委会 | 研究权限范围内的重要事项 | 满足人数、讨论、表决和记录后形成党委决定 |

每次会议都可选择：

- **自由磋商**：所有 NPC 每轮并行判断是否发言；多人想发言时随机选一人；
- **玩家主持**：玩家点名发言、追问、归纳或转入表决。

MVP 必须实现：

- 至少 4 名 NPC 同时参会；
- “无人愿意发言”的沉默状态；
- 一人和多人希望发言的两种路径；
- 玩家随时发言并撤销正在生成的 NPC 发言；
- 出席、列席和表决资格区别；
- 会议后 NPC 通气、文件任务和行动意图；
- 会前从玩家有权访问的文件中多选会议材料，按版本向全体与会者开放；
- 会议中可临时追加文件，发送动作、版本和知情范围进入会议记录；
- 参会 Agent 能在发言轮中使用联系人、文件和亲历记录工具，工具副作用随有效发言原子提交；
- 正式决定与一般讨论意见的效力区别。

## 9. 面谈、调研和文件

### 9.1 面谈

玩家可以与市长、秘书长、常委、区县、部门、企业、银行和上级单独交谈。会谈结束后，对方可以：

- 改变对玩家或议题的看法；
- 联系另一个角色通气；
- 起草文件或请求材料；
- 执行权限内的核查和准备；
- 提出需要玩家或会议批准的行动；
- 选择暂时不做任何事。

这些后续行为并不全部向玩家公开。

面谈过程中，玩家可以暂时切回晨报、文件、市情资料、日程、工作记录和私人笔记本，之后返回原谈话；切换不会结算场景或重新扣点。工作记录只显示“与某人进行了面谈”，不展示具体对话。私人笔记可增删改，但不进入角色 Agent 上下文、不形成正式效力。

### 9.2 调研

至少提供：

- 北山焦化园区；
- 北山县人社服务中心或职工安置点；
- 一处防汛风险点。

通知调研和“四不两直”产生不同的信息偏差。现场叙述必须来自规则已经确定的观察结果。

### 9.3 文件与上级报告

MVP 至少支持：

- 秘书 Agent 按玩家要求起草一份报告；
- 玩家退回并附修改意见；
- 下级报告原样转呈或加呈报说明；
- 文件版本、作者、引用、签发和收件人记录；
- 上级收到后立即回应、要求补充、延迟处理或暂不处理；
- 文件起草跨日完成并进入晨报收件箱。
- 玩家已经批阅、退回、转办或报送的文件在次日进入归档区，不继续占用待阅列表。
- 会议材料不改写原文件权限或正式效力；未参会人物不能读取，仅亲历者可随冻结会议记录回读当时版本。

## 10. 动态事件候选

内容包可以提供候选，但不能绑定固定日期。

### 10.1 产业类

- 企业现金流恶化或短期缓解；
- 银行要求补充材料、收紧或维持授信；
- 工人欠薪、离职或聚集风险；
- 订单、技术团队或资产处置变化；
- 监测数据出现矛盾；
- 县里补报、继续低报或改变口径。

### 10.2 组织与程序类

- 某常委要求把事项列入会议；
- 材料因风险评估或合法合规意见不足被退回；
- 会议人数不足、人员请假或需要回避；
- 会后纪要与部分人理解不一致；
- 私下承诺被第三人得知；
- 下属因任务过载拖延或转交。

### 10.3 上级与外部类

- 上级要求补报、约谈、核查或暂不反应；
- 省级部门改变报送口径或时间窗口；
- 媒体追问、网络视频被证实或证伪；
- 降雨、事故隐患和其他条件化外部冲击。

候选是否发生由前置条件、人物行动、状态和随机种子决定。某些事件在一局中可以永远不发生。

## 11. 隐藏事实与变化

MVP 可以保留一组开局隐藏事实，例如：

- 县里上报就业人数明显低于真实影响；
- 企业可自由抵押资产少于其口头陈述；
- 前任专题会存在模糊的国企参与承诺；
- 某项重组方案产业上可行但融资合规风险高；
- 某处防汛风险点最近一次照片与文字结论不完全一致。

这些事实不是按日期自动揭晓。只有相应人物说出、文件暴露、调研观察、核查完成或事件传播后，才进入玩家视野。

开局事实本身也可以在保持结构约束的前提下按种子变化，例如企业最紧张的现金流节点、哪一处材料矛盾更严重、哪些角色已经私下通气。变化内容必须在场景允许范围内生成并写入初始世界事实，不能让 LLM 在中途随意改写过去。

## 12. 一条可能但不固定的试玩轨迹

下面只说明系统能够产生什么，不是推荐流程：

1. 第一天玩家批阅水利局报告，要求补附件；与市长面谈后预约第三天去北山调研。
2. 面谈后市长让财政部门内部核算风险，并向常务副市长询问国企方案；这些行为在当天场景结算中产生。
3. 第二天晨报收到秘书起草的上级简报草稿，县委书记同时请求先与玩家谈话。
4. 玩家原样转呈县里报告，省里两天后追问就业数字来源；另一局中，玩家先退回核查，上级可能只记录按期报送。
5. 第三天调研自动触发并扣除 2 点。由于玩家没有提前通知，现场负责人不在，但玩家看到了与书面材料矛盾的用工记录。
6. 玩家临时召开座谈会；自由磋商中企业和县里都等待对方先表态，会议出现沉默。
7. 玩家点名环保局长后，多人希望回应，随机选中市长先发言。
8. 会后县委书记联系工业副市长通气，秘书开始整理纪要，企业提出一项需要正式程序的行动意图。
9. 日终降雨风险没有触发，但水利补充报告逾期，次日晨报出现提醒。

换一个玩家顺序或随机种子，这些日期、信息和反应都应改变。

## 13. 模板模式

模板模式不是把旧六回合文本继续串起来，而是一个确定性 Stub Agent 系统：

- 发言意愿由角色状态和固定规则产生；
- 发言、文件和行动意图使用可参数化模板；
- 同一输入和种子产生相同结构化结果；
- 可以连续推进至少 7 天；
- 能覆盖会议沉默、多人抢话、玩家中断、文件起草、上级延迟反应和日程冲突；
- 不需要 API Key 或网络。

模板模式首先服务于规则验证，不要求具有实况模式的语言变化度。

## 14. 网页原型范围

### 14.1 必须有

- 开局身份和 DeepSeek API Key 门禁；
- 每日晨报、收件箱、日历和行动点；
- 文件阅读、批示、退回、转呈和版本查看；
- 未来日程预约、冲突提示和到日自动触发；
- 个别面谈；
- 多人会议两种讨论方式和玩家中断；
- 会议创建与会议日程中的会前材料多选，以及会议中的临时材料发送；
- 有通知与“四不两直”现场调研；
- 秘书起草上级报告和提交现有文件；
- 会后结算、日终结算和次日局势更新；
- 人物公开档案、玩家已知关系与历史记录；
- 可查阅的城市自然、社会、经济、基础设施和六个县区公共资料；
- 本地存档、重新开始和固定种子模板模式。
- 默认关闭的 Agent 调试开关，可实时查看轮次、工具名称、成败、协议修复、收敛与降级状态，但不泄漏 NPC 私有内容、不可见文件正文、隐藏思维链或 API Key。

### 14.2 暂不做

- 完整五年任期和退休；
- 多城市、完整城市地图和自由行走；
- 所有现实会议类型和专项程序；
- 语音或多人游戏；
- Agent 的主机文件系统、Shell 和任意网络工具；
- 无限制角色常驻运行和无限 Agent 对话；
- 自动抓取现实新闻；
- 复杂宏观经济模型。

## 15. 成功标准

内部试玩至少满足：

1. 玩家能连续推进 7 个游戏日，且没有固定剧情步骤阻止自由顺序；
2. 第二局至少有三项晨报内容、人物反应或事件日期与第一局不同；
3. 玩家能说明会议类型、讨论方式和正式效力不是一回事；
4. 至少一次会议出现沉默、抢话或玩家中断；
5. 被取消的 NPC 发言不进入记录、记忆或后果；
6. 至少一名 NPC 在会后主动联系他人或起草文件；
7. 玩家预约的未来活动在执行日自动开启并扣点；
8. 上级报告能够使用秘书草稿或下级文件，并保留来源；
9. 至少一个上级反应延迟出现，或因条件未满足而没有出现；
10. 坏结果可追溯到信息、程序、资源、人物行动或随机流；
11. 玩家 DTO 和每个 Agent 上下文均不泄漏隐藏事实；
12. 模板模式无需网络即可完成完整七日回放。
13. 市委常委能够识别完整常委班子，所有角色上下文中的人物资料不泄漏他人私人目标、记忆和内部认知。
14. Agent 只能读取有权限的文件和本人亲历记录；被打断或校验失败的工具写操作不进入存档；
15. 人物工具使用供应商原生 Tool Calls，128 轮为硬上限、32 轮内完成为强目标；Prompt 明确要求避免重复或无关调用，输出截断、内容过滤和工具参数错误能够被区分诊断。
16. 面谈和会议中的人物正式发言按模型原生流式分块到达并立即显示，前端不模拟逐字打字；玩家在流式输出期间发言时，未完成内容不会进入正式记录。
17. 面谈可在不改变场景版本的情况下收起并返回；工作记录不泄漏具体对话，玩家私人笔记不进入任何角色上下文且不消耗行动点。
18. Agent 重复工具调用会被拦截，第 32 轮起强制终止；连续无法提交有效终止结果时丢弃暂存副作用并给出可见安全答复，调试模式能够解释这条收敛路径而不泄漏隐藏信息。
19. 会前和会中发送的材料绑定发送时版本，全体与会者可通过 Agent 文件工具读取，未参会人物和玩家无权文件不能借会议接口泄漏。

## 16. MVP 实施状态

1. 先以领域模型实现逐日时间、行动点、日程和文件工作流；
2. 让模板角色完成七日无 LLM 回放；
3. 加入个别面谈和场景后结算；
4. 加入多人会议、并行发言意愿与玩家中断；
5. 加入调研观察和上级报告；
6. 加入 Agent 记忆、文件工具、通气和行动提议；
7. 删除或隔离旧固定六回合流程；
8. 试玩校准每日成本、会议长度和日终 Agent 数量。

上述核心步骤已经形成首个可运行版本。下一阶段先通过试玩校准每日成本、会议长度、角色记忆和日终调用预算；在纵向切片稳定前，不扩展完整仕途、第二座城市或多人模式。

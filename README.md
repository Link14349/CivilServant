# CivilServant

> 一个以虚构中国地方治理为背景、由 LLM 辅助驱动的单人政治治理模拟游戏。

玩家扮演一名地方领导干部。游戏按自然日推进：每天阅读晨报和来文，安排日程，与不同人物面谈或开会，到现场调研，向上级提交报告，并在有限行动点内决定自己亲自关注什么、授权谁处理什么。

游戏的重点不是寻找预先写好的正确选项，而是在不完整信息、人物立场、组织程序、文件流转和长期责任之间作出判断。

## 当前状态

仓库已经从“十二周六回合事件链”迁移为可运行的**逐日开放模拟 MVP**。当前版本可以在网页中连续推进日期，并以模板模式或 DeepSeek 实况模式运行人物互动。

这意味着：

- 固定十二周流程和预写回合已经取消；
- 每日晨报、4 点行动预算、日程和日终推演已经接入；
- 面谈、会议、调研、文件流转和向上报送均可从网页操作；
- 多人会议支持自由磋商、玩家主持、异步发言和玩家中断；
- 实况模式下，人物发言、会后意图和上级材料反应由各自隔离上下文的 Agent 生成；
- 当前仍是用于验证核心循环的单城 MVP，不包含完整任期、调任、晋升、处分和退休。

## 目标玩法

### 每日工作循环

```text
晨报：昨日新闻、内部报告、请示、上级通知和今日日程
  ↓
批阅文件与安排未来日程
  ↓
消耗行动点进行会议、面谈、现场调研或向上面谈
  ↓
各场景结束后，NPC 通气、起草文件或提出后续行动
  ↓
日终结算：执行、信息传播、外部变化和延迟反应
  ↓
生成下一天晨报
```

### 核心机制

- **每日行动点**：暂定每天 4 点。面谈、会议、调研和上级面谈分别消耗固定点数。
- **文件批阅不扣行动点**：玩家可以阅读、批示、退回、转呈和签发真实到达收件箱的有限文件。
- **可预定日程**：今天可以安排未来某日调研、会议或面谈，在实际执行日扣除行动点。
- **动态强制日程**：上级召见、突发事件和固定活动可能挤占原有安排，需要改期、取消、委托或拒绝。
- **多人会议**：每个角色由独立 Agent 扮演，拥有自己的认知、记忆、文件和立场。
- **两种讨论方式**：自由磋商由角色并行判断是否发言；玩家主持时由玩家点名。
- **玩家可以打断**：玩家发言优先，被取消的 NPC 生成不会进入会议记录、记忆或游戏状态。
- **会后仍会发生事情**：人物可以彼此通气、起草文件、提交报告或提议行动。
- **现场调研不是上帝视角**：有通知调研与“四不两直”各有信息偏差、访问限制和组织反应。
- **向上汇报依赖文件**：玩家可以让秘书起草，也可以转呈下级材料；来源、版本和签发责任都会保留。
- **后果可以延迟或不发生**：上级和其他人物可以建立条件化反应，也可能暂不采取后续行动。

## 设计原则

- **玩家是领导者，不是超级项目经理**：玩家决定目标、红线、授权、议程和重大分歧；执行方案由具体人物与机构形成。
- **事实、认知和材料分离**：NPC 不共享上帝视角，玩家看到的也是经过渠道筛选的材料。
- **会议类型决定权限**：座谈会、专题会、协调会和常委会的正式效力不同；讨论方式不会凭空增加权限。
- **Agent 只能提议，规则内核负责裁决**：LLM 负责语言、意图和文书，权限、资源、随机事件和状态变化由模拟内核决定。
- **承诺和责任结构化保存**：私下承诺、文件版本、会议记录、证据和未完成任务不会只存在于聊天摘要。
- **动态而非预写**：事件来自期限、状态、人物行动和条件化随机冲击，不按固定日期播放同一故事。

## 模型与 API Key

默认配置：

```text
API Base URL: https://api.deepseek.com
Model:        deepseek-v4-flash
```

API Key 的处理原则：

- 默认只保存在浏览器 `sessionStorage`，关闭浏览器后清除；
- 只有勾选“记住 Key”后才写入 `localStorage`；
- Key 通过请求头临时传给本机 FastAPI；
- 后端不把 Key 写入数据库、存档或日志；
- 模板模式不调用真实模型。

## 本地运行

环境要求：

- Python 3.9+
- Node.js 20+
- npm 10+

在项目根目录执行：

```bash
python3 -m venv .venv
.venv/bin/pip install -e 'backend[dev]'

cd frontend
npm install
npm run build
cd ..

.venv/bin/uvicorn civilservant.main:app --app-dir backend/src --reload
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。没有 API Key 时可以进入模板调试模式。

## 目标架构

```text
React + TypeScript 工作台
          │ HTTP + SSE
          ▼
FastAPI 应用服务
    ├── 每日循环与日程编排
    ├── 会议 / 面谈 / 调研场景
    ├── Agent Harness 与有限上下文
    ├── 虚拟文件系统与文书流转
    ├── 确定性模拟与日终结算
    └── SQLite 事件日志与快照
```

Agent 的文件能力只作用于游戏内文档库。Agent 没有主机文件系统、Shell、数据库写入或任意网络权限。

## 开发与验证

运行后端测试：

```bash
.venv/bin/pytest backend/tests
```

构建前端：

```bash
cd frontend
npm run build
```

逐日版本包含无 LLM 连续七日回放测试，并覆盖：

- 日程预约、冲突与执行日扣点；
- 多人会议中的沉默、抢话和玩家中断；
- NPC 认知隔离与会后行动；
- 文件版本、权限、提交和上级延迟反应；
- 日终结算、动态事件和确定性随机流；
- 保存、重载及重复请求不重复推进。

## 内容边界

- 城市、人物、企业、数字和事件均为虚构，不对应现实个案；
- 不使用真实在任官员作为 NPC，也不收集未公开个人信息；
- NPC 不以“清官、贪官、忠臣、派系”等单一标签塑造；
- 违法违规选择会产生审计、举报、纪律和跨任期后果；
- 项目不提供规避监督、调查、审计或执法的现实操作指南；
- 公共治理、诚实报告和行政能力建设具有真实游戏价值，但不保证善意必然成功。

## 参与项目

这是一个已经能运行核心循环、仍处于早期验证阶段的原型。欢迎通过 Issue 提交：

- 每日行动是否过多或过少；
- 会议发言是否自然、是否有人知道了不该知道的信息；
- 文件流转和正式效力是否令人困惑；
- NPC 的会后行为能否从身份、任务和记忆中解释；
- 动态事件是否仍像换皮的预写剧情；
- 新事件候选、人物关系或架构建议。

提交代码前请先阅读 [AGENTS.md](AGENTS.md) 和 `docs/` 中的设计文档。

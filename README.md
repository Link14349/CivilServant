# CivilServant

> 一个以虚构中国地方治理为背景、由 LLM 辅助驱动的单人政治治理模拟游戏。

玩家扮演一名刚到任的地方领导干部。在有限权力、有限财政、不完整信息和多重责任约束下，你需要阅读互相矛盾的材料，与上下级和利益相关方谈话，决定目标与红线，把任务交给具体的人执行，并承担承诺、程序和责任留下的长期后果。

当前版本提供一段可完整游玩的六回合纵向切片：玩家担任虚构城市“岚州市”的市委书记，在十二周内处理北岭焦化产业整改。完整任期、跨岗位调任、晋升与退休系统仍在规划中。

## 它与普通选项游戏有什么不同？

CivilServant 的核心不是寻找一个标准答案，而是在具体人物、制度程序和资源约束之间建立一条能够运转的责任链。

- **玩家是领导者，不是超级项目经理**：你决定目标、优先级、红线、授权对象和重大分歧；预算、技术路线和执行清单通常由市长、分管领导和部门形成。
- **信息不是上帝视角**：世界事实、NPC 认知和呈给玩家的材料彼此分离。人物可能不知道、误判、隐瞒或只说对自己有利的部分。
- **可以直接找人谈**：每回合拥有有限会谈时段，可询问情况、试探态度、私下交办或提出条件交换。
- **私下谈话不能替代正式程序**：谈话可以形成摸底、准备和私人承诺；重大资金、关停、重组和人事事项仍需通过相应程序取得正式效力。
- **决定落实到具体责任人**：每个正式选择都会标明牵头人、参与单位、实施程序和责任记录，后续偏差也会追溯到具体执行链。
- **承诺会被记住**：条件交换、会议纪要、数据矛盾、财政责任和未完成任务会跨回合存在。
- **LLM 不裁定胜负**：模型负责理解自由输入、扮演人物和生成叙事；规则引擎负责权限、资源、指标、随机冲击和最终结算。

## 当前可玩内容

“岚州市产业整改”是一局约 30—45 分钟的短局：

1. 阅读事件卷宗和四份口径矛盾的材料；
2. 约谈市长、秘书长、县委书记、部门负责人、企业和银行等人物；
3. 在合规整改、就业稳定、财政风险和产业延续之间确定方向；
4. 选择由谁起草方案，并处理各方提出的条件；
5. 通过私下沟通、条件交换和正式会议形成责任链；
6. 面对执行偏差和省级复核，得到阶段评价与未来风险预告。

每个回合都支持预设选项和“其他·自拟指令”。模板模式无需 API Key，适合快速试玩和自动化回归；实况模式默认使用 DeepSeek V4 Flash 驱动自由输入和人物会谈。

## 快速开始

### 环境要求

- Python 3.9+
- Node.js 20+
- npm 10+

### 安装并启动

在项目根目录执行：

```bash
python3 -m venv .venv
.venv/bin/pip install -e 'backend[dev]'

cd frontend
npm install
npm run build
cd ..

.venv/bin/uvicorn civilservant.main:app --app-dir backend/src --reload
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。

- 有 DeepSeek API Key：验证后进入实况模式；
- 没有 API Key：选择“进入模板调试模式”，仍可完成六回合游戏。

如果提示 `Address already in use`，说明 8000 端口已有服务运行。可以直接打开上面的地址，或先结束占用该端口的旧进程。

## 模型与 API Key

默认配置：

```text
API Base URL: https://api.deepseek.com
Model:        deepseek-v4-flash
```

API Key 的处理方式：

- 默认只保存在浏览器 `sessionStorage`，关闭浏览器后清除；
- 只有勾选“记住 Key”后才写入 `localStorage`；
- Key 通过请求头临时传给本机 FastAPI；
- 后端不把 Key 写入数据库、游戏存档或日志；
- 模板模式完全不调用模型。

高级设置允许修改模型名和 API Base URL，但服务不会在模型不可用时静默切换到其他供应商。

## 系统架构

```text
React + TypeScript 网页端
          │
          │ HTTP
          ▼
FastAPI 应用服务
    ├── 玩家视图与会话版本控制
    ├── NPC / 指令 LLM 适配器
    ├── 确定性模拟与结算规则
    └── SQLite 本地存档
```

核心边界：

- React 只展示玩家有权看到的数据，不在前端复制模拟规则；
- NPC Agent 只接收自己的身份、局部认知、公开材料、正式决定和亲历谈话；
- Agent 无权直接修改数据库或世界状态；
- 所有状态变化均经过 Pydantic 契约和规则引擎校验；
- 同一随机种子和同一结构化行动可以复现相同结算。

## 开发与验证

运行后端测试：

```bash
.venv/bin/pytest backend/tests
```

检查并构建前端：

```bash
cd frontend
npm run build
```

测试默认不得访问真实模型 API。人物认知隔离、会谈时段、私下交办、正式化、确定性回放和完整六回合流程均使用模板或固定响应验证。

## 内容边界

- 城市、人物、企业、数字和事件均为虚构，不对应现实个案；
- 不使用真实在任官员作为 NPC，也不收集未公开个人信息；
- NPC 不以“清官、贪官、忠臣、派系”等单一标签塑造；
- 违法违规选择会产生审计、举报、纪律和跨任期后果；
- 项目不提供规避监督、调查、审计或执法的现实操作指南；
- 公共治理、诚实报告和行政能力建设具有真实游戏价值，但不保证善意必然成功。

- 某项选择的后果无法从资源、权限、程序或人物动机中解释；
- 新事件链、人物关系或技术实现建议。
